Crop-Making Protocol — Tomogram Datasets

Reconstructed from Grace's walkthrough · captured by voice transcription · drafted 24 June 2026

This is the end-to-end procedure Grace demonstrated for making ER/organelle crops from collaborator tomogram datasets, using Fileglancer, Neuroglancer, and Amira. The flow is: locate the dataset → define the ROI → cut the crop in Amira → verify it lines up → file a GitHub issue for the annotators.

0. Before you start

Collaborators place their dataset in their own designated Drive folder, and it then shows up in Fileglancer. Per Gudrun's policy, labs hold onto their own data rather than copying it into a PTR drive.

  • Permissions: you need both read and write on the collaborator's folder. Labs often grant read-only and forget write — chase this early, it's a common source of delay.
  • Fileglancer paths are Linux-style. Don't paste a Windows path. Use the directory shown under cluster / Linux, not the Windows mount.
  • Browser quirk: Fileglancer sometimes misbehaves in Chrome. If it's acting up, try a different browser or clear the cache before assuming a real problem.

1. Open the dataset in Neuroglancer

  1. In Fileglancer, navigate to the collaborator's drive and into their designated folder. (Example given: a FuncEworm dataset — drill down through the folder ending in the dataset name, into the recon folder, until the thumbnail appears.)
  2. Click the thumbnail and choose Open with Neuroglancer.
  3. Neuroglancer loads the full EM/tomogram volume.

2. Get the ROI (bounding box)

Two cases, depending on the collaborator:

If they give you the ROIs (some draw bounding boxes; some give coordinates directly) — use what they send. If they want to draw them, walk them through:

  1. Create a new tab in Neuroglancer.
  2. Go to local → annotate, tick the annotation box, and switch the type to annotation — this creates a new annotations tab.
  3. In that tab, click the bounding-box annotate icon.
  4. Ctrl + left-click + drag to start the box, scroll to navigate through depth, then Ctrl + left-click again at the far corner to close the box.
  5. Read off the XYZ coordinates it displays — those go into Amira to cut the crop.

If they don't give ROIs — scroll through the volume yourself, find a good region, draw the box the same way, and use those coordinates.

Watch the axis order. Coordinates come out as XYZ on some datasets and ZYX on others — it depends on the data. Confirm the order before you trust the numbers. (In the live example, the dataset was ZYX while Amira expected XYZ, which caused a mismatch.)

3. Make the crop in Amira

  1. Open a new Amira project.
  2. Open any recent dataset as a placeholder (you'll delete it later).
  3. Right-click the placeholder → Python scripts → Zarr Read → Create.
  4. For the input directory, navigate to the folder holding the .zarr files.
  5. Pick your resolution level. s0 is the highest resolution; the number climbs as resolution drops (s6 is lowest in the example). Fileglancer shows s0 coordinates.
  6. Set the X, Y, Z limits from your ROI coordinates.
Resolution scaling — the fiddly part. Fileglancer reports coordinates at s0. If you cut at a lower resolution (e.g. s1), you must divide the coordinates by the right factor. The .zattrs / attributes file is supposed to tell you the divisor per level, but Grace finds it unreliable. Her practical method: start dividing by 2; if the crop doesn't light up in the right place, try 4, then 6 (or 8). Scaling usually follows a power series — 2, 4, 6, 8 or 4, 8, 16, 32. If you cut at s0 (highest res), use the raw numbers with no division.

This convention varies by team — each team does it slightly differently, but a given team stays consistent. Track each team's divisor convention (you're planning a spreadsheet for this).

4. Clean up the crop edges

Once the crop is made, inspect it in Amira and confirm you're looking at the right region.

If the crop includes structures that are tricky to annotate or regions you want the annotators to avoid, trim them off so they don't cause problems downstream:

  1. Identify the unwanted region (example: looking at the XY plane, an unwanted slab at the ends of the Z stack).
  2. Go to project and shift/move the volume slightly so those end slices are excluded.
  3. Repeat until the crop contains only what you want annotated.

5. Export the crop to Zarr

Export from the LABELS, not the raw data. Right-click the labels object → Python scripts → (Zarr write) → Create. If you export the raw image instead, any segmentation work won't come along. The team uses one shared output Zarr for both crop-making and labels — there is no separate crop-only file.
  1. Right-click the labels object (not raw data) → Python scripts → Create.
  2. Set the output directory. Keep the Amira file and the exported segmentations together in one folder — different labs want crops saved in different directories, so consolidating avoids confusion.
  3. Name the output folder ending in .zarr — Zarr write only writes to a folder with that extension. Create the folder, select it, apply.
  4. Wait for "save complete."

6. Verify it lines up in Neuroglancer

  1. In Fileglancer, find the label you just exported (under the PTR/Neuroglancer area).
  2. Open it in Neuroglancer, right-click → copy source.
  3. Create a new tab, paste the source, and import as segmentation.
  4. Right-click → annotate, then right-click to jump directly to where the crop sits.
  5. Confirm the crop lands where the ROI was. If it lines up, the crop succeeded.

7. Save and name the Amira project

  1. Delete the placeholder file — you don't need it anymore. You should be left with the raw data and the label.
  2. File → Save Project, choose the second option: minimize project computation, confirm OK.
  3. Save the project into the same folder as the exported Zarr.
  4. Rename the Amira files so naming is consistent everywhere (the example renamed to match the dataset + crop, e.g. Pancreas5_soma_7 style).
  5. Copy the saved directory path — you'll paste it into the GitHub issue so annotators know where to look.

Naming convention

Grace's scheme (flexible — scientists generally don't specify): DatasetName (what's annotated) N

  • Dataset name — as it appears in Fileglancer / as the collaborator gave it.
  • In parentheses — what must be annotated in that crop (e.g. soma, endocrine). A soma crop shows only soma; an endocrine crop only endocrine.
  • Trailing number — which crop it is in the series (10th, 11th, etc.). Check GitHub for the current count and continue from there.

8. File the GitHub issue for annotators

Shorten the Neuroglancer URL first — Neuroglancer stores all state in the URL, so it gets too long to paste around. Paste the long link into the shortener, click the blue button, and copy the short version.

  1. Open a new GitHub issue for the annotators.
  2. Paste the shortened Neuroglancer link into the issue body and into the dedicated column for easy access.
  3. Add the Amira project directory path (so they know where the crop lives).
  4. State what to annotate — you don't always annotate everything in a crop (sometimes just ER, sometimes just one organelle). For this example: "annotate soma in this crop."
  5. Include the project code.
  6. Include the Fileglancer link so annotators can see context outside the crop and identify structures more easily.
  7. Once every field is filled, move the issue to the annotation queue.

9. The annotation cycle (what happens next)

  1. An available annotator assigns themselves and moves status from Annotation → In Progress Annotation (so you can see what's being worked on).
  2. When their first pass is done, they put it on the screening queue and unassign.
  3. A second person assigns themselves, screens it, screenshots what needs separating vs. re-annotating, assigns it back to the original annotator, and sets it to Fix.
  4. This loop repeats until nothing is left to fix.
  5. You give the final check: confirm the Zarr is exported to the right place, everything opens correctly in Fileglancer/Neuroglancer.
  6. Notify the collaborators that the crop is ready.
